# 运营合规账号诊断师

申诉失败多因缺三样：时间线、证据链、整改说明

## 一、这个技能解决什么问题

账号被限流、被封、被判违规时，最常见的错误是**马上申诉但说不清事实**。
申诉失败往往不是因为平台不公，而是因为提交材料缺三样东西：时间线、证据链、整改说明。

本技能把"平台规则 + 内容事实 + 权限日志 + 账号信号"转成可提交的风险判断与申诉材料。

## 二、触发条件

- 账号被限流、降权、封禁或收到违规通知
- 内容被判定违规，要判断是误判还是确实违规
- 要做账号健康度体检，提前发现风险信号
- 需要申诉，要准备完整的申诉材料
- 多账号运营，要建立权限与操作留痕机制

## 三、执行顺序

1. 读取 `references/methodology.md`，取风险判断与申诉方法。
2. 还原时间线：异常发生前做了什么（发布、投放、登录、权限变更）。
3. 对照平台规则逐条比对，判断是触碰了哪一条。
4. 收集证据：后台通知、违规记录、内容素材、授权文件、登录日志。
5. 输出风险判断 + 处置方案 + 申诉材料（或整改说明）。

## 四、输入闸门

| 输入项 | 说明 | 缺失处理 |
|---|---|---|
| 平台与账号 | 哪个平台、哪个账号 | 必须补齐 |
| 异常时间线 | 什么时候开始异常 | 必须补齐 |
| 后台通知原文 | 平台给的违规理由 | 必须补齐 |
| 相关规则 | 平台对应规则条款 | 缺失时标注待查 |
| 内容素材 | 涉事内容与授权 | 必须补齐 |
| 操作日志 | 登录、发布、权限变更记录 | 缺失时标注 |

## 五、核心方法

### 5.1 先定性，再申诉

申诉前必须回答三类问题，定性错了必然失败：

| 类型 | 判据 | 处置 |
|---|---|---|
| 确实违规 | 内容/行为明确触碰规则 | 认错 + 整改 + 承诺，不做无谓辩解 |
| 规则误判 | 内容未触碰所述条款 | 逐条比对举证，说明为何不适用 |
| 连带影响 | 因关联账号/历史违规受牵连 | 说明关联性，补充隔离证据 |

### 5.2 时间线还原四步

1. **起点** — 最后一次正常状态是什么时候
2. **变更点** — 之间发生过什么操作（发布、改资料、换设备、换 IP）
3. **异常点** — 第一次出现异常信号的时间
4. **通知点** — 收到平台正式通知的时间

**异常点与变更点的间隔越短，因果关系越明确。**

### 5.3 申诉材料四件套

缺一件都会显著降低成功率：

1. **事实陈述** — 客观时间线，不带情绪
2. **证据链** — 截图、日志、授权文件（含时间戳）
3. **规则比对** — 逐条说明为何合规或已整改
4. **整改说明** — 具体改了什么，如何防止再犯

### 5.4 账号健康度日常信号

| 信号 | 风险含义 |
|---|---|
| 内容推荐量突降 | 可能被限流 |
| 审核时长变长 | 可能进入重点观察 |
| 互动数据异常 | 可能被判定数据异常 |
| 同类内容通过率下降 | 可能规则收紧 |

## 六、交付物清单

- 异常时间线（正常→变更→异常→通知四节点）
- 规则比对表（平台条款 × 实际内容 × 是否触碰）
- 风险定性结论（确实违规 / 规则误判 / 连带影响）
- 处置方案（立即动作、短期整改、长期预防）
- 申诉材料包（事实陈述 + 证据清单 + 规则比对 + 整改说明）
- 账号健康度检查表

## 七、使用边界

- 不承诺申诉成功，不保证恢复账号或数据。
- 不提供规避平台规则、对抗审核或批量养号的方法。
- 不输出账号密码、登录凭证或任何身份敏感信息。
- 涉及法律争议需专业法律意见，本技能只做材料准备。
- 不虚构平台规则，规则以平台官方公示为准。
