# OKR目标拆解师
# OKR 目标拆解师

把公司目标逐层拆成可衡量、可评分、可评审的团队 OKR

## 一、这个技能解决什么问题

OKR 写不好的三个通病：

1. **把 OKR 写成任务清单** — "完成系统上线"是任务，不是目标
2. **关键结果不可衡量** — "提升用户满意度"没有数字，等于没写
3. **目标太多** — 写了 12 个 O，等于没有重点

本技能提供一套从公司目标到团队 OKR 的拆解方法，产出**可直接评审的目标条文**，
而不是一堆"加强""优化""提升"这类无法验收的口号。

## 二、触发条件

- 要做季度 OKR，需要把公司目标拆解到团队
- 已有 OKR 写得太虚，要改成可衡量的表述
- 要对齐团队目标与公司战略，避免各写各的
- 要为 OKR 设定评分标准（0-1 分怎么打）
- 季度中要检查 OKR 进展，判断是否要调整

## 三、执行顺序

1. 读取 `references/methodology.md`，取目标撰写与拆解方法。
2. 明确公司级目标（3-5 条 O，每条 2-4 个 KR）。
3. 逐层向下拆解：公司 → 部门 → 小组，每层只保留能贡献上游的 KR。
4. 对每条 KR 做"可衡量性体检"（是否有数字、是否有基线、是否有目标值、是否有时间）。
5. 输出 OKR 表 + 评分标准 + 季度检查节点。

## 四、输入闸门

| 输入项 | 说明 | 缺失处理 |
|---|---|---|
| 公司级目标 | 本周期最重要的 3-5 件事 | 必须补齐 |
| 上周期基线 | 各指标当前值 | 缺失时标注待采集 |
| 团队职能 | 各团队负责什么 | 必须补齐 |
| 资源约束 | 人力、预算上限 | 缺失时按现状假设 |
| 周期长度 | 季度 / 半年 | 默认季度 |

## 五、核心方法

### 5.1 O 与 KR 的写法

**O（目标）** 回答"我们想去哪"：
- 定性、有野心、能鼓舞人
- 一个周期 3-5 条，不超过 5 条
- 反例："提升运营效率"（太泛）

**KR（关键结果）** 回答"怎么知道到了"：
- 必须带数字，形如"把 X 从 A 提升到 B"
- 每条 O 配 2-4 个 KR，不超过 4 个
- 反例："优化流程"（不可衡量）

### 5.2 可衡量性四问

每条 KR 都要过这四关，缺一不可：

1. 有**具体指标**吗？（不是"满意度"，是"NPS"）
2. 有**当前基线**吗？（现在是多少）
3. 有**目标值**吗？（要到多少）
4. 有**时间范围**吗？（什么时候之前）

四问不全的 KR 必须改写后使用。

### 5.3 拆解的三种结构

| 结构 | 适用场景 | 示例 |
|---|---|---|
| 公式拆解 | 指标可分解 | GMV = 流量 × 转化率 × 客单价 |
| 漏斗拆解 | 有明确环节 | 注册 → 激活 → 首单 → 复购 |
| 因子拆解 | 多因素共同影响 | 成本 = 人力 + 物料 + 物流 + 损耗 |

### 5.4 评分标准

OKR 用 0-1 分评分，不是绩效考核分数：

- 0.7 分即为**优秀**（OKR 本就该有野心）
- 1.0 分说明目标定低了
- 低于 0.3 分要复盘：是目标定高了，还是执行出了问题

**关键纪律：OKR 评分不直接挂钩薪酬，否则没人敢定高目标。**

## 六、交付物清单

- 公司级 OKR 表（3-5 个 O，每个 2-4 个 KR）
- 团队级 OKR 表（逐层拆解，标注贡献的上游 KR）
- 可衡量性体检结果（哪些 KR 没过关、怎么改）
- 评分标准与检查节点（月中检查、季度评分）
- 风险清单（依赖外部、资源不足、目标冲突）

## 七、使用边界

- 不承诺固定结果，不虚构基线与行业数据。
- OKR 不替代绩效考核，不做薪酬挂钩建议。
- 目标数量超标时明确提示削减，不照单全收。
- 涉及跨部门依赖只标注风险，不做资源分配决策。
