# 供应商管理师
# 供应商管理师

按支出与风险分层，对供应商配不同管理强度，把力气花在真正重要的地方

## 一、这个技能解决什么问题

供应商管理的两大失败模式：

1. **签完就不管** — 合同签完锁进抽屉，出问题才发现对方早就不达标
2. **一刀切管理** — 对战略供应商和办公耗材供应商用同一套管理强度，浪费精力

本技能按**风险与重要性分层**，对不同层级的供应商配不同管理强度，把力气花在真正重要的地方。

## 二、触发条件

- 要建供应商准入、评估与分级机制
- 供应商数量多，不知道该重点管谁
- 要设计 SLA 条款并持续追踪达标情况
- 某个供应商频繁出问题，要做风险分类与处置
- 要做年度供应商评审，决定续约、降级还是替换

## 三、执行顺序

1. 读取 `references/methodology.md`，取供应商分层与 SLA 设计方法。
2. 运行 `scripts/vendor_scorer.py` 对供应商打分（交付、质量、成本、响应、风险）。
3. 运行 `scripts/vendor_risk_classifier.py` 做风险分级。
4. 运行 `scripts/sla_compliance_tracker.py` 追踪 SLA 达标情况。
5. 输出供应商分层管理方案与处置建议。

## 四、输入闸门

| 输入项 | 说明 | 缺失处理 |
|---|---|---|
| 供应商清单 | 名称、品类、合同额 | 必须补齐 |
| 交付记录 | 准时率、质量合格率 | 缺失时标注待采集 |
| 合同关键条款 | SLA、违约金、续约条件 | 必须补齐 |
| 依赖度 | 替换难度、可替代供应商数 | 必须补齐 |
| 风险事件 | 历史事故 | 缺失时按无记录 |

## 五、核心方法

### 5.1 供应商分层（按支出 × 风险）

| 层级 | 特征 | 管理强度 |
|---|---|---|
| 战略伙伴 | 高支出 + 高依赖 | 季度评审、联合改善、高层互访 |
| 重要供应商 | 高支出 或 高依赖 | 月度跟踪、年度评审 |
| 一般供应商 | 中低支出、可替代 | 半年度抽检 |
| 交易型 | 低支出、易替换 | 只管付款与交付结果 |

### 5.2 SLA 设计的四要素

一条可用的 SLA 必须包含：

1. **指标定义** — 明确算什么（如"准时交付率 = 按时到货批次 ÷ 总批次"）
2. **目标值** — 达标线是多少
3. **测量方式** — 谁测、多久测一次、数据从哪来
4. **未达标的后果** — 整改要求、违约金、降级或退出

**没有后果的 SLA 是装饰品。**

### 5.3 风险分级与处置

| 风险等级 | 判据 | 处置 |
|---|---|---|
| 高 | 独家供应 + 频繁违约 + 无备选 | 立即开发备选、缩短合同周期 |
| 中 | 有违约但可替换 | 加强监控、准备备选 |
| 低 | 表现稳定、市场充分竞争 | 常规管理 |

### 5.4 评分维度

建议五个维度加权：

| 维度 | 权重建议 | 说明 |
|---|---|---|
| 交付 | 30% | 准时率、完整性 |
| 质量 | 25% | 合格率、返工率 |
| 成本 | 20% | 价格竞争力、降本贡献 |
| 响应 | 15% | 沟通效率、问题响应速度 |
| 风险 | 10% | 财务稳定性、合规、集中度 |

## 六、交付物清单

- 供应商分层清单（层级、管理强度、评审频率）
- 评分结果表（五维评分 + 加权总分 + 排名）
- 风险分级与处置建议（高/中/低 + 对应动作）
- SLA 条款模板（四要素齐全）
- SLA 达标追踪表
- 年度评审结论（续约 / 整改 / 降级 / 退出）

## 七、使用边界

- 不承诺固定结果，不虚构供应商数据或评价。
- 涉及合同签署与法律条款需法务确认。
- 不做具体商业贿赂或不当利益相关的建议。
- 供应商评分仅供内部决策参考，不直接对外披露。
